# 画布优化路线图

## 总目标

让画布在项目规模从少量节点增长到大量媒体节点、连线和批量交互时，依然保持稳定、清晰、顺滑。

这份路线图会按阶段推进。每个阶段都应尽量小，可以独立实现、验证和发布。

## 成功标准

- 单节点拖拽、多选框拖拽、持久分组拖拽、画布拖拽都保持流畅。
- 选择、框选、连线、右键菜单、小地图、键盘操作之间不会互相打架。
- 大工作流里避免在高频交互中反复全量扫描 `nodes` 和 `links`。
- 视觉效果保持高级感，但不会拖垮渲染性能。
- 画布关键行为有聚焦测试覆盖，包括几何计算、框选、拖拽、连线创建。

## 阶段 1：批量拖拽性能优化

优先级：高

现状问题：
多选框拖拽已经可用，但当前批量移动仍可能在拖拽帧里触发多次节点位置更新。选中节点较多时，会增加 React 更新压力。

优化目标：

- 增加 `updateNodePositions` 工作流 API，一次性更新多个节点坐标。
- 多选框拖拽和持久分组拖拽都改用这个批量 API。
- 保持单节点拖拽行为不变。
- 保留网格吸附和 `Alt` 拖拽不吸附的现有规则。

验收标准：

- 多选拖拽时，每一帧只触发一次节点状态更新。
- 原有单节点拖拽测试继续通过。
- 新增测试覆盖批量位置更新和历史记录持久化。

## 阶段 2：选择状态模型整理

优先级：高

现状问题：
当前画布选择状态分散在 `selectedNodeId`、`selectedNodeIds`、`selectedGroupId`、`selectedLinkId` 等状态里。后续继续加多选能力时，这些状态容易互相冲突。

优化目标：

- 引入统一的选择模型，例如：
  - `none`：无选择
  - `node`：单节点
  - `nodes`：多节点
  - `group`：持久分组
  - `link`：连线
- 把选择状态切换集中到 `useCanvasSelection` hook。
- 集中管理“什么时候清空选择”的规则。
- 保留现有规则：滚轮平移、滚轮缩放、中键/滚轮拖动画布不会取消框选态。

验收标准：

- 任意时刻只会有一种选择模式生效。
- 点击、Shift 点击、框选、连线选择、空白点击都有测试覆盖。
- 除非明确要改，否则现有 UI 行为保持不变。

## 阶段 3：高频查询路径优化

优先级：高

现状问题：
画布里多处逻辑会反复对 `nodes` 和 `links` 做 `find`、`filter`、`some`。节点少时问题不明显，但节点和连线多起来后，拖拽、连线、hover、渲染 overlay 都会受影响。

优化目标：

- 增加 memo 化索引：
  - `nodeById`
  - `linksBySourceNodeId`
  - `linksByTargetNodeId`
  - `linkKeySet`
- 在连线校验、overlay 渲染、输入解析、选择辅助逻辑中逐步使用这些索引。
- 保持工具函数简单、可测试。

验收标准：

- 连线重复校验不再每次从头扫描全部 links。
- overlay 渲染路径减少重复 `nodes.find`。
- 测试覆盖重复连线、节点缺失、端口缺失等情况。

## 阶段 4：连线渲染降负载

优先级：中

现状问题：
当前连线视觉比较丰富，包含多层 path 和流动动画。效果好，但当连线数量变多时，SVG path 和动画会变重。

优化目标：

- 静态普通连线尽量交给 canvas/Leafer 层绘制。
- React/SVG overlay 只负责少量交互态：
  - 草稿连线
  - 选中连线
  - hover 连线
  - 与当前激活节点相关的连线
- 增加密度策略：连线数量较高时自动降低或暂停流动动画。
- 避免对非交互连线重复渲染多套视觉层。

验收标准：

- 连线较多时画布仍然可以顺畅平移和缩放。
- 选中、hover、草稿连线仍然清晰可见。
- 普通规模下的连线视觉不降级。

## 阶段 5：节点卡片渲染边界拆分

优先级：中

现状问题：
媒体节点组件较大，职责比较多。继续增加交互功能后，重渲染风险和维护成本都会上升。

优化目标：

- 把大型节点卡片拆成更小的组件：
  - 外壳、标题、动作按钮
  - 媒体预览
  - 端口
  - 模型和参数控制
  - 上传、帧提取等操作区
- 把布局计算抽到纯工具函数。
- 给昂贵的媒体预览区域建立更明确的 memo 边界。

验收标准：

- 组件文件更容易阅读和定位问题。
- 图片、视频、音频、文本节点现有行为保持不变。
- React hook dependency warning 逐步减少，而不是增加。

## 阶段 6：多选能力完善

优先级：中

现状问题：
多选已经支持框选、虚线包围框、批量连线、整体拖拽，但还可以继续补成更完整的临时组能力。

优化目标：

- `Delete` / `Backspace` 删除所有选中节点。
- 复制选中的多个节点。
- 粘贴多节点时保持相对位置。
- 复制/粘贴时保留选中节点内部的连线，并正确重映射节点 id。
- 增加对齐、分布命令。
- 支持方向键微调整个选区。
- 可选：在虚线框附近显示一个轻量的多选工具条。

验收标准：

- 多节点操作保持相对布局。
- 复制选区时，选区内部连线能正确复制到新节点之间。
- 无效命令会被禁用或给出清晰提示。

## 阶段 7：交互策略收敛

优先级：中

现状问题：
画布交互规则分散在 App 组件和多个 hook 中。现在还能维护，但后续继续加能力时，小改动容易影响其它交互。

优化目标：

- 明确并集中以下策略：
  - 空白点击什么时候清空选择
  - 什么时候开始框选
  - 什么时候开始画布拖拽
  - 什么时候单节点拖拽升级为多选拖拽
  - 菜单什么时候关闭
- 能抽成纯函数的策略尽量抽成工具函数。
- 给最近新增和最容易回归的交互补测试。

验收标准：

- 不需要通读整个 App 组件，就能理解核心交互规则。
- 最近新增的框选、多选拖拽、批量连线都有回归测试。

## 阶段 8：性能测量与调试工具

优先级：中

现状问题：
性能优化需要可复现的基线。否则优化后只能凭感觉判断。

优化目标：

- 增加开发环境专用的画布调试信息，或提供 console helper：
  - 节点数量
  - 连线数量
  - 当前选中数量
  - 可视节点数量，如果后续做视口裁剪
  - 拖拽帧平均更新时间
- 增加一个可快速生成大工作流的本地测试 fixture。
- 记录如何 profile 拖拽、连线渲染和节点重渲染。

验收标准：

- 开发者可以快速复现大画布场景。
- 每个优化阶段都能做前后对比。

## 阶段 9：可选视口裁剪

优先级：低，除非大画布性能已经成为明显瓶颈

现状问题：
如果所有 React 节点卡片始终全部渲染，超大画布下会有压力。

优化目标：

- 根据 pan、zoom、viewport size 计算当前可视世界区域。
- 只完整渲染视口附近的节点卡片。
- 远处节点必要时渲染轻量占位。
- 保持连线、小地图、搜索、fit-view 等功能正确。

验收标准：

- 大工作流在局部放大编辑时保持响应。
- 视口外节点仍然参与搜索、小地图、布局和连线计算。

## 建议推进顺序

1. 批量拖拽性能优化。
2. 高频查询路径优化。
3. 选择状态模型整理。
4. 多选删除、复制、粘贴、对齐等能力。
5. 连线渲染降负载。
6. 节点卡片渲染边界拆分。
7. 交互策略收敛。
8. 性能测量与调试工具。
9. 如果 profile 证明有必要，再做视口裁剪。

## 当前状态记录

- 已支持框选多个节点。
- 已支持更明显的虚线多选框和更大的内边距。
- 已支持框选态批量拖拽连线。
- 已支持框选态整体拖拽。
- 已支持在虚线框内部任意位置拖拽整个临时组。
- 框选态内的节点不会显示单节点点击激活态。
- 阶段 1 已完成第一轮核心优化：
  - 新增 `updateNodePositions` 批量坐标更新 API。
  - 多选框拖拽改为每帧一次批量更新。
  - 持久分组拖拽也改为批量更新组内节点。
  - 单节点拖拽仍保留原有行为。
- 阶段 2 已完成第一轮核心收敛：
  - 新增 `CanvasSelection` 统一选择模型。
  - 新增选择模型到旧 App 状态的适配层。
  - 节点选择、Shift 多选、框选完成、连线选择、组选中、空白清空等主要入口已统一走 selection model。
  - 当前仍保留 `selectedNodeId`、`selectedNodeIds`、`selectedGroupId`、`selectedLinkId` 等旧状态作为组件传参，后续可以继续下沉到 `useCanvasSelection` hook。
- 阶段 3 已完成第一轮核心优化：
  - 新增 `CanvasGraphIndex`，统一构建 `nodeById`、`linkKeySet`、`linksBySourceNodeId`、`linksByTargetNodeId`。
  - 连线重复校验支持使用 `linkKeySet`，减少重复扫描 links。
  - 连线端点查询支持使用 `nodeById`，减少重复扫描 nodes。
  - `useCanvasLinking`、连线 overlay、草稿连线 overlay、文本节点 connected 状态判断已接入索引。
  - 连线写入逻辑改用当前节点/连线 ref 作为基准，降低同一事件中“新增节点后立即连线”读到旧闭包数据的风险。
- 阶段 4 已完成第一轮渲染降负载：
  - 新增 `linkRenderPolicy`，集中管理连线动画和 glow/filter 的密度策略。
  - 普通规模下保留完整 active link 动画效果。
  - 连线数量较高或画布动画暂停时，active link 自动降级为轻量静态高亮。
  - 批量草稿连线数量较高时，自动关闭 pulse 动画和 glow filter，保留基础草稿线可见性。
- 阶段 5 已完成第一轮节点卡片渲染边界拆分：
  - 新增 `InlineNodePortHandle` 共享端口组件，统一 input/output 端口的 class、pointer 事件、title 和 `data-*` 标记。
  - 文本、图片、视频、音频节点的内联端口已接入共享组件，减少四类节点卡片中的重复交互代码。
  - 新增端口 class 计算测试，覆盖 input/output 和 active 状态。
  - 顺手修正图片/视频节点内若干 hook 依赖问题，减少 React Compiler 对节点卡片 memo 化的阻塞。
- 阶段 6 已完成第一轮多选能力完善：
  - `Delete` / `Backspace` 支持删除当前选中的所有节点，并清理相关连线和节点输出。
  - `Ctrl/Cmd+C` 支持复制当前多选节点，复制内容只包含选区内部连线。
  - 粘贴多节点时保持相对位置，并为节点和内部连线重新生成 id；编号节点标题会按当前画布继续续号。
  - 虚线框上方新增左/中/右、上/中/下对齐，以及水平/垂直分布命令。
  - 对齐/分布作为离散命令写入历史记录，支持撤销。
  - 新增 `multiSelectionOperations` 纯函数测试，覆盖复制、粘贴、内部连线重映射和布局命令。
- 下一步建议继续阶段 6，补齐多节点复制时的 nodeOutputs 保留策略，以及方向键微调整个选区。
